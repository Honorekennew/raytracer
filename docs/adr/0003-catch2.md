# 3. Use Catch2 as the testing framework

> Draft: the reasons below come from the repository contents, not from the team's board. Replace or confirm them before accepting.

## Context

The project follows test-driven development: a test is written first and fails, then the code is
written to make it pass. C++ has no built-in test framework, so we need a library that makes
tests short to write, shows clear failure messages, and works with CTest (see ADR 2).

Alternatives:

- GoogleTest.
- doctest.
- Plain `assert` calls or a home-made test runner.

## Decision

We use Catch2 version 3 (pinned to v3.7.1). Tests are written as `TEST_CASE` with `REQUIRE`
checks in `tests/`. `Catch2::Catch2WithMain` provides the `main()` function, and
`catch_discover_tests` registers every `TEST_CASE` with CTest.

Catch2 is taken from the system if a compatible version is installed, and downloaded with CMake's
`FetchContent` otherwise.

## Status

Proposed

## Consequences

- Readable tests, with a failure message that shows both values, for example
  `"Hello!" == "Hi!"`.
- Little setup: adding a test means adding a file and listing it in `tests/CMakeLists.txt`.
- Comparing floating point numbers, which a ray tracer will need, is covered by `Catch::Approx`.
- The first configuration needs internet access to download Catch2.
- Catch2 is compiled from source, which adds build time on the first build. The first build in
  the dev container took 114 steps, most of them for Catch2.
- Tests depend on Catch2's macros, so switching to another framework later means rewriting them.
- The version is pinned, so upgrading Catch2 is a manual change.
